# 02 统一学习记录与数据契约

## 1. 目标

统一学习记录解决五个问题：

1. 任意学习形态都能出现在“继续学习”；
2. 任意用户产出都能进入次日回顾；
3. 所有有效学习时间采用同一统计口径；
4. 日志和周视图可以自动生成；
5. 内容包升级后仍能找回笔记、进度和历史。

它不是新的内容仓库。原始教材、题目、章节笔记、个人解析和主观题答案继续保存在各自适合的位置；统一记录只保存索引和引用。

## 2. 最小数据模型

优先升级现有 `data/activity.json`，不要在没有必要时再创造一套并行数据库。建议新 schema 在保留旧 `days` 与 `last_section_id` 兼容读取的同时，为每日增加通用活动记录。

概念示例：

```jsonc
{
  "schema_version": 3,
  "days": {
    "2026-09-02": {
      "activities": [
        {
          "activity_id": "stable-local-id",
          "activity_type": "read",
          "domain": "medicine",
          "subject_id": "endodontics",
          "resource_id": "book-id",
          "item_id": "section-or-question-id",
          "started_at": "2026-09-02T09:00:00+08:00",
          "last_active_at": "2026-09-02T09:24:00+08:00",
          "duration_seconds": 1320,
          "resume_target": {
            "view": "reader",
            "resource_id": "book-id",
            "item_id": "section-id"
          },
          "output_refs": [
            {
              "kind": "section_note",
              "id": "section-id",
              "path": "data/notes/section-id.md"
            }
          ],
          "result_state": "has_output"
        }
      ],
      "review": {
        "state": "pending",
        "completed_at": "",
        "result_ref": null
      }
    }
  }
}
```

字段可以根据当前代码调整，但语义必须稳定。禁止把正文、完整题目或整篇笔记复制进活动索引。

## 3. 活动类型

初期只需要五种：

| activity_type | 含义 | 典型产出 |
| --- | --- | --- |
| `read` | 教材、讲义、词汇和阅读资料 | 章节笔记 |
| `objective_practice` | 政治或英语客观题 | 答案、正确性、个人解析 |
| `subjective_practice` | 翻译、作文、名词解释、简答、论述 | 个人答案、反思、AI 批改结果 |
| `notebook` | 英语周记或未来的自由学习笔记 | Markdown 内容或当日片段 |
| `review` | 对某个历史学习日的统一回顾 | 一份回顾结果 |

不要为完形、阅读理解、作文、政治选择题分别创造活动类型。题型差异保存在活动元数据或对应题库中。

## 4. 学科与来源

每条记录必须同时具有：

- `domain`：`medicine / politics / english`；
- `subject_id`：稳定学科标识，例如马原、牙体牙髓、考研英语一；
- `resource_id`：具体书籍、题库或试卷；
- `item_id`：小节、题目、题组或主观题的稳定标识。

回顾页面首先按 `domain` 分组，再按 `subject_id` 分组。不得继续把每一本书直接称为一个“学科”。

## 5. 继续学习

每种活动必须提供可恢复的 `resume_target`。今日页选择继续项时遵循：

1. 优先恢复最近明确未完成的活动；
2. 没有未完成项时恢复最近一次有效活动；
3. 同一时刻首页只突出一个主要继续入口；
4. 可以在次级列表展示少量最近活动，但不铺满全部历史。

恢复目标示例：

- 阅读：书籍 ID + 小节 ID；
- 政治练习：题库 ID + 知识位置 + 当前题号；
- 英语真题：年份题库 + 题型组 + 当前题号；
- 主观题：资料 ID + section ID；
- 英语笔记：周标识 + 当前日期锚点；
- 回顾：被回顾日期。

## 6. 统一计时

当前计时只覆盖章节阅读。重构后所有学习工作区共享同一套规则：

- 工作区在前台且存在当前活动时计时；
- 页面隐藏、离开工作区或关闭活动时暂停；
- 连续 10 分钟没有滚动、输入、选择、提交或页面导航时暂停；
- 恢复交互后继续；
- 每次写入带有活动类型、学科和资源标识；
- 不因为自动保存或程序刷新制造重复时间；
- 外部读取接口继续提供总秒数，并增加按学科、活动类型的聚合；
- 历史旧数据无法可靠细分时保留为 `read`，不猜测重分类。

活跃日以真实有效活动时长为依据，不再只认可阅读页。单纯打开页面几秒不应形成有意义的学习日，可使用与现有数据相容的最小有效阈值，但阈值必须在文档和测试中固定。

## 7. 用户产出引用

次日回顾只汇集用户产生或确认过的内容：

- 非空章节笔记；
- 客观题错误、标记不确定的题目、非空个人解析；
- 非空主观题答案、反思和侧边栏批改结果；
- 英语笔记中属于该日期的片段；
- 已保存的其他学习笔记。

仅阅读但没有笔记的活动仍显示标题、位置和时长，但默认不复制原书正文进入回顾。页面可以提供“回到原文”。

## 8. 稳定 ID 与别名

稳定 ID 是数据安全边界，不只是内部实现细节。

必须建立别名映射，例如：

```jsonc
{
  "schema_version": 1,
  "section_aliases": {
    "old-section-id": {
      "current_id": "new-section-id",
      "confidence": "exact-source-range",
      "reason": "package replacement retained same source lines"
    }
  }
}
```

规则：

- 优先依据书籍 ID、来源行区间、原始标题、章节位置和内容哈希自动匹配；
- 高置信度映射可以自动生效，但必须生成报告；
- 无法可靠匹配的笔记进入“未归档内容”只读列表，不能删除或静默忽略；
- 读取笔记、活动和复习来源时先解析别名；
- 新包发布验证必须检查旧稳定 ID 是否仍存在或有明确别名；
- 以后替换内容包时，稳定 ID 漂移属于 blocker。

## 9. 派生视图

以下内容全部由统一记录派生，不再拥有独立事实来源：

- 今日继续项；
- 今日轨迹；
- 最近有效学习日；
- 待回顾日期；
- 每日日志；
- 周视图；
- 活跃天数与连续学习；
- 医学、政治、英语时间分布；
- 阅读、练习、主观作答、笔记、回顾时间分布。

题库正确率、单书进度、词汇完成情况仍属于各自资料内部指标，不进入统一精力统计的主比较区。
