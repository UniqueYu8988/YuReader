# 05 分阶段实施路线

## 1. 执行纪律

本路线用于目标模式持续执行，但不允许把所有阶段合并成一次大改。

每个阶段必须依次完成：

1. 阅读该阶段涉及的真实代码与数据；
2. 记录阶段前基线；
3. 只实现该阶段范围；
4. 运行自动测试和真实浏览器验证；
5. 更新 `docs/STATUS.md`，只写真实完成能力；
6. 建立独立 Git 提交；
7. 通过停止条件后再进入下一阶段。

若工作区在开始时已有未提交修改：

- 先列出并判断来源；
- 不回滚、不覆盖、不把无法归因的修改冒充本阶段成果；
- 与本阶段不重叠时绕开；
- 与本阶段重叠且无法安全区分时停止并说明，不猜测处理。

## 2. 阶段 0：契约与基线

### 目标

让项目最高优先级说明与新的统一学习目标一致，并形成可重复比较的真实基线。

### 工作范围

- 读取根 `AGENTS.md`、`README.md`、`docs/STATUS.md`、本目录全部设计文档；
- 将 `AGENTS.md` 中“练习不参与复习和日志”的旧规则调整为：练习界面与正文保持独立，但其活动、用户产出、计时可以进入统一记录和回顾；
- 明确四个全局概念：今日、学习库、回顾、记录；
- 将 `docs/PLATFORM_UPGRADE.md` 标注为历史阶段设计，不删除；
- 生成只读基线审计，记录书籍、题库、章节、笔记、活动、练习、主观题、日志、周报、Obsidian 和 API 摘要；
- 为现有功能补足最关键的基线测试，但不改界面。

### 不做

- 不迁移数据；
- 不改变首页或导航；
- 不创建新活动 schema；
- 不删除旧文件。

### 停止条件

- 文档不再互相矛盾；
- 基线报告可以重复生成且不读取/提交真实笔记正文；
- 现有测试、健康接口和真实书架正常；
- 记录所有当前失联笔记与无法映射活动。

## 3. 阶段 1：稳定 ID 与用户数据安全

### 目标

在任何界面重构前，确保现有笔记、阅读进度和 Obsidian 存档不再因内容包替换而失联。

### 工作范围

- 建立 section ID 别名 / 迁移映射格式和加载器；
- 自动审计当前所有非空笔记；
- 根据旧包、来源区间、标题、章节位置和内容哈希恢复高置信度映射；
- 为无法匹配内容提供只读“未归档内容”数据接口或报告；
- 所有笔记读取、统计和复习来源解析别名；
- YuBook 包替换验证增加稳定 ID 漂移检查；
- 保存迁移证据、数量、字节数和哈希对比。

### 不做

- 不移动或重写原笔记；
- 不让模型猜测章节对应；
- 不改变主导航；
- 不清理旧数据目录。

### 停止条件

- 每个非空笔记要么映射到当前小节，要么明确出现在未归档清单；
- 笔记文件数量、总字节数和哈希没有意外变化；
- 当前书籍阅读和笔记保存没有回归；
- 未来包替换若导致无别名的稳定 ID 漂移会被验证器阻断。

## 4. 阶段 2：统一学习记录索引

### 目标

让阅读、客观题、主观题、英语笔记和回顾共享同一活动事实来源，同时保持原内容存储方式不变。

### 工作范围

- 升级现有 `activity.json` schema，保留旧字段兼容；
- 实现幂等的旧数据回填；
- 为五类活动建立共同字段与 `resume_target`；
- 阅读、客观题、主观题、英语笔记和回顾写入统一索引；
- 统一计时器覆盖所有学习工作区；
- 外部阅读时长接口兼容旧响应，并增加按学科和活动类型聚合；
- 提供统一活动的只读查询与自动测试；
- 继续把笔记、解析和答案保存在原文件，只记录引用。

### 不做

- 不改首页视觉；
- 不替换现有复习页面；
- 不改变题型工作区；
- 不删除旧活动字段。

### 停止条件

- 五类活动均能产生去重记录；
- 旧阅读总秒数得到保留；
- 同一活动不会因心跳、刷新或双读重复统计；
- 每种活动都能给出有效恢复目标；
- 外部时长接口继续可用。

## 5. 阶段 3：今日页与跨模块继续学习

### 目标

把首页从入口集合改造成每日学习起点。

### 工作范围

- 新增或重构今日聚合数据；
- 首页按“待回顾 → 继续学习 → 今日轨迹 → 三科入口”排列；
- 继续学习支持所有活动类型；
- 医学、政治、英语进入对应学习库；
- 最近资料只显示有限数量；
- Obsidian、统计、真题和笔记不再作为八个平级首页卡片；
- 保持主题、窗口缩放和当前视觉基线。

### 不做

- 不在本阶段删除旧书架的真题 / 笔记入口；
- 不重做复习与记录页面；
- 不增加自动任务计划。

### 停止条件

- 真实浏览器可以分别从首页恢复阅读、客观题、主观题和笔记；
- 没有活动时空状态简洁且可进入三科学习库；
- 首页不因扫描全部正文或笔记产生明显首开阻塞；
- 深浅主题、宽屏与收窄窗口无溢出、无控制台错误。

## 6. 阶段 4：统一回顾与自动每日记录

### 目标

用一次自然的次日回顾替换“逐书待办 → 全部完成 → 生成日报 → 再总结”的流程。

### 工作范围

- 回顾日期从统一索引选择最近未回顾的有效学习日；
- 动态汇集章节笔记、错题/个人解析、主观答案/反思和英语笔记片段；
- 按 domain 与 subject 分组；
- 保留一个主要回顾结果输入框；
- 支持保存文本回顾或显式标记无文本回顾；
- 每日记录视图自动存在，不依赖 AI 总结；
- 旧日志、旧回顾和旧周报进入兼容历史；
- 将回顾结果镜像到新的 Obsidian 学习记录结构，失败时回退本地。

### 不做

- 不内置 AI API；
- 不强制逐学科完成；
- 不复制原书正文；
- 不删除旧 review/log/weekly 数据。

### 停止条件

- 一个真实学习日中至少包含两种不同活动，下一日能在同一回顾页正确汇集；
- 保存一次回顾结果即可完成该日期；
- 即使不保存 AI 总结，每日记录仍可查看；
- 回顾内容可逐项回到原始笔记或题目；
- Obsidian 不可用时不阻断网页保存。

## 7. 阶段 5：学习库与导航收敛

### 目标

让学科、资料、行为和工具回到各自正确层级。

### 工作范围

- 全局主导航收敛为今日、学习库、回顾、记录；
- 学习库内部保留医学、政治、英语；
- 真题归入英语，但保持高可见入口和年度导览；
- 英语周记归入英语个人笔记；
- 政治讲义与题库、医学教材与未来主观题按学科聚合；
- 全局工具区保留主题与 Obsidian；
- 旧入口先做兼容重定向，再从主界面移除；
- 页面继续继承现有视觉系统，不重新造组件库。

### 不做

- 不改变正文、题目或书籍内容；
- 不强行让三科资料页完全同构；
- 不扩建新的学习模块。

### 停止条件

- 用户只需理解学科与今日/回顾/记录四个概念；
- 任何现有资料不超过三次明确点击即可到达；
- 返回路径一致且不会丢失当前活动；
- 旧深链接仍能打开或安全重定向。

## 8. 阶段 6：统计与周视图收敛

### 目标

让统计只反映真实精力投入，让周报变为可选总结而非流程门槛。

### 工作范围

- 统计页归入记录；
- 统一展示总时长、三科学科分布、活动类型分布、活跃日和连续学习；
- 热力图使用全部有效学习时长；
- 题库正确率留在题库详情；
- 单书进度留在资料主页；
- 周视图自动汇集每日记录；
- 允许粘贴可选 Gemini 周总结并保存，但没有总结时周视图仍完整。

### 停止条件

- 同一秒学习时间只被统计一次；
- 医学 + 政治 + 英语 + 其他兼容项与总时长可解释；
- 阅读 + 客观题 + 主观题 + 笔记 + 回顾与总时长可解释；
- 只做题或只回顾的一天也被识别为活跃日；
- 历史阅读时间没有消失。

## 9. 阶段 7：兼容层退休与清理

### 目标

在真实使用验证后减少代码和入口冗余，不删除用户内容。

### 前置条件

- 新流程至少完成两个不同日期的真实闭环；
- 所有验收项通过；
- 旧数据完整备份；
- 用户确认新导航与回顾方式可用。

### 工作范围

- 停止向旧 review-workflow、独立日志流程和强制周报流程写入；
- 移除不再可达的旧 UI、事件处理器和兼容 API；
- 保留历史文件只读导入；
- 清理确定无引用的测试输出、缓存和临时文件；
- 更新 README、STATUS 和数据恢复说明；
- 进行最终全量回归。

### 停止条件

- 不存在两套同时写入的学习流程；
- 不存在失效按钮或隐藏但仍执行的旧事件监听器；
- 旧历史仍能在记录页查看；
- 用户数据与书籍内容哈希无意外变化。

## 10. 遇到问题时的优先级

发生冲突时按以下顺序决策：

1. 用户数据不丢失；
2. 原书与题库不被改写；
3. 现有核心学习路径继续可用；
4. 统一数据契约正确；
5. 交互简洁；
6. 视觉细节；
7. 代码整洁。

不能为了更快完成后续阶段牺牲前四项。
