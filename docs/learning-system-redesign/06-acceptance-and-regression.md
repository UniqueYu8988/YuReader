# 06 验收与回归标准

## 1. 验收原则

自动测试通过不等于重构完成。每阶段需要同时验证：

- 数据没有丢失；
- 真实用户流程可完成；
- 页面行为与文档一致；
- 旧资料与旧历史仍可访问；
- 浏览器没有明显错误、阻塞和布局回归。

所有测试使用本地、匿名或专用测试数据。不得把真实书籍、笔记内容、答案和 Obsidian 文本提交到 Git。

## 2. 永久数据不变量

以下项目在整个重构期间必须保持：

- OneDrive 原始教材、PDF、Word、MinerU 原始产物不修改；
- `content/` 正式包和 `question-banks/` 题库不因本次重构被重新清洗；
- 阶段 0 捕获的书籍数、题库数、小节数若发生变化，必须有本阶段明确原因；
- 迁移前后的非空用户笔记数量、总字节数和 SHA-256 可逐项对照；
- 客观题正式提交、个人解析、主观题答案和反思不减少；
- 旧日志、周报和英语周记均可继续打开；
- Obsidian 不可用时本地保存仍然工作。

## 3. 自动测试矩阵

### 3.1 数据与迁移

- 旧 schema `activity.json` 可以无损读取；
- schema 升级可重复运行，第二次运行不产生重复活动；
- section alias 可以解析旧笔记与旧活动；
- 别名链路有循环或目标不存在时安全失败；
- 无法映射的非空笔记进入未归档清单；
- 空笔记不会伪装成学习产出；
- 旧复习、日志和周报读取兼容；
- 原子写入中断不会留下半个 JSON 或 Markdown。

### 3.2 活动与计时

- 阅读、客观题、主观题、笔记、回顾分别产生正确活动类型；
- 心跳重复提交使用幂等键，不重复累计；
- 切后台、离开页面和 10 分钟无交互后暂停；
- 滚动、输入、选择答案或导航后恢复；
- 活动时间正确归属 domain、subject 和 resource；
- 外部时长接口保留旧字段并返回新增聚合；
- 只有客观题或回顾活动的一天也可成为活跃日。

### 3.3 继续学习

- 阅读恢复到稳定小节；
- 政治练习恢复到题库、知识位置和题号；
- 英语真题恢复到年份、题型组和题号；
- 主观题恢复到原题和未完成答案；
- 英语笔记恢复到当前周；
- 回顾恢复到被回顾日期；
- 目标不存在时提供可理解的回退，不进入空白工作区。

### 3.4 回顾与记录

- 选择最近未回顾的有效学习日，而不是机械选择昨天；
- 同一来源不会因本地与 Obsidian 双份保存而重复出现；
- 回顾正确汇集章节笔记、错题/个人解析、主观题答案/反思和英语笔记片段；
- 只读未写笔记的活动只显示轨迹，不复制正文；
- 一次保存回顾结果即可完成日期；
- 不保存 AI 总结时，每日记录仍存在；
- 周视图在没有周总结时仍存在；
- 保存回顾不会修改源章节笔记、题目或原书解析。

### 3.5 统计

- 总时长等于去重后的活动时长；
- 按学科聚合与总时长可解释；
- 按活动类型聚合与总时长可解释；
- 历史阅读时长保留；
- 题量和字数不会混入时间分布；
- 题库正确率仍可在题库内部查看。

## 4. 真实浏览器场景

至少建立一套专用测试日期数据并完成以下闭环：

### 场景 A：医学阅读

1. 从今日进入医学教材；
2. 打开真实小节并滚动；
3. 打开笔记，输入测试 Markdown，等待自动保存；
4. 离开后从今日恢复；
5. 确认活动、时长和笔记引用存在。

### 场景 B：政治讲义与练习

1. 从政治资料页进入有真实关联的练习；
2. 提交一题；
3. 保存个人解析；
4. 返回资料页和今日；
5. 确认继续位置、题目结果和解析引用存在。

### 场景 C：英语真题

1. 进入一个真实年份试卷导览；
2. 打开完形或阅读题组；
3. 保存部分答案后离开；
4. 从今日恢复到正确年份、题组和位置；
5. 不提前暴露答案或解析。

### 场景 D：英语主观题

1. 打开翻译或作文；
2. 保存测试答案与反思；
3. 关闭后恢复；
4. 确认内容进入统一活动与下一次回顾来源。

### 场景 E：跨类型次日回顾

1. 使用前述测试活动形成一个有效学习日；
2. 将系统日期或测试参数切换到下一日；
3. 今日页出现一项待回顾；
4. 回顾页同时显示医学笔记、政治解析和英语答案；
5. 粘贴一次测试回顾 Markdown；
6. 保存后待办完成，记录页显示该日期；
7. 源笔记与答案未被改写。

### 场景 F：无学习日与补回顾

1. 中间留出一个没有活动的日期；
2. 系统应选择最近尚未回顾的有效学习日；
3. 不生成空日报或空复习任务。

## 5. 视觉与交互验收

每次涉及页面的阶段至少检查：

- 深色和浅色主题；
- 1280×800 与更宽桌面窗口；
- 侧边栏存在时的收窄窗口；
- 基础移动端烟雾检查，至少不能出现内容完全不可达；
- 页面无横向溢出、底部截断、悬浮按钮贴边和弹层出屏；
- 首次进入资料或活动时有稳定加载状态，不显示残缺旧页面；
- 浏览器控制台 0 error；
- 返回、继续、保存和 Obsidian 按钮语义一致；
- 键盘焦点和文本输入不会被全局快捷键抢走。

本轮不追求重新设计移动端，但不能破坏已有可用性。

## 6. 性能验收

- `/api/bootstrap` 不同步读取全部正文和全部笔记内容；
- 今日页只读取聚合索引，不扫描全部书籍正文；
- 回顾页按所选日期读取引用内容，不加载整个历史；
- 统计来自聚合索引，不在每次打开时遍历全部 Markdown；
- 首次加载出现明确骨架或加载状态，不能暴露半渲染资料主页；
- 同一页面重复打开应复用合理缓存，同时保存后能正确刷新。

不设脱离实际机器的绝对毫秒指标。每阶段记录重构前后同一真实页面的可重复测量，出现明显回退必须解释或修复。

## 7. 每阶段通用回归

- `python -m py_compile app.py`；
- `node --check static/app.js`；
- YuReader 全量单元测试；
- YuBook 与 YuPractice 回归测试；
- `/api/health`、`/api/bootstrap`、涉及的新旧接口；
- 真实医学书、政治讲义、英语方法资料、英语真题各抽查一个；
- Markdown 标题、表格、长文本、笔记保存；
- 浏览器控制台与关键视口截图；
- `git diff --check`；
- `git status` 中没有误提交真实数据、缓存、截图或大型产物。

## 8. 最终完成判定

只有同时满足以下条件，统一学习系统重构才算完成：

- 用户每天只需从今日开始；
- 任意活动均可继续；
- 任意用户产出均可进入下一次回顾；
- 一次回顾即可形成完整每日记录；
- 周视图与统计不要求额外生成；
- 所有学习时长口径统一；
- 用户旧数据无丢失、无静默失联；
- 主导航中不再混合学科、资料类型、用户行为和工具；
- 旧兼容流程停止新写入，但历史仍可访问；
- 用户无需阅读复杂说明即可完成真实两日学习闭环。
