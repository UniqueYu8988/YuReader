# YuReader 统一学习系统重构总纲

状态：设计基线，尚未开始实现  
制定日期：2026-09-02  
适用项目：`C:\Users\Yu\Documents\YuReader`

## 1. 为什么需要这次重构

YuReader 已经从本地 Markdown 阅读器扩展为包含医学教材、政治讲义与题库、英语方法课、历年真题、主观题、章节笔记、英语周记、昨日复习、日志、周报和统计的个人学习平台。现有功能大多可以单独工作，但它们来源于不同阶段的局部需求，缺少共同的数据与交互契约。

当前主要矛盾不是功能缺失，而是：

- 首页是入口集合，不是每日学习起点；
- 医学、政治、英语是学科，真题是资料类型，笔记是用户行为，却被放在同一级导航；
- 阅读、选择题、英语主观题和周记分别保存，无法共同进入“继续学习”和昨日回顾；
- 复习只读取前一天修改的章节笔记，忽略错题、个人解析、主观题答案和英语笔记；
- 日志、周报是复习流程的附加产物，跳过复习就没有完整记录；
- 统计混用阅读时长、题量、正确率和字数，不能清楚回答精力投向；
- 内容包升级曾造成稳定小节 ID 漂移，已有笔记仍在磁盘上，但无法被当前目录、统计和复习找到。

本次重构的目标不是增加新模块，而是把现有模块收敛为一条每日可重复的学习主线：

```text
今日需要做什么
  → 阅读 / 做题 / 背诵 / 写作
  → 自动留下统一学习记录
  → 下次从任何未完成活动继续
  → 下一学习日一次性回顾
  → 自动形成长期记录与统计
```

## 2. 最终产品模型

全局只保留四个用户概念：

1. **今日**：待回顾、继续学习、今日轨迹、三科学习入口。
2. **学习库**：医学、政治、英语及其阅读资料、练习和笔记。
3. **回顾**：汇集最近一个尚未回顾的有效学习日，不强制逐书完成。
4. **记录**：每日历史、周视图和统一统计；不再要求用户主动“生成日志”。

Obsidian 是保存目的地，不是一个需要学习的业务模块。主题切换、打开 Obsidian 等属于全局工具，不占据主导航。

## 3. 核心设计原则

### 3.1 一个学习事实来源

继续学习、昨日回顾、日志和统计必须来自同一份“统一学习记录索引”，不能分别扫描不同目录后自行猜测。

统一索引只记录活动元数据和用户产出引用，不复制原书正文，也不取代现有 Markdown 笔记。

### 3.2 内容可以不同，流程必须相同

医学教材、政治选择题、英语阅读、完形填空、翻译、作文和未来的名词解释可以拥有不同界面，但都遵守：

```text
进入内容 → 产生学习活动 → 保存自己的产出 → 记录可继续位置 → 纳入次日回顾
```

### 3.3 AI 仍由浏览器侧边栏提供

YuReader 不接入付费模型 API。网页负责提供清晰、适量、可追溯的上下文和一个统一粘贴位置；Gemini 侧边栏负责理解、提问、批改、复习和总结。

AI 结果永远不能覆盖原书正文。AI 或用户生成的内容必须明确属于笔记、个人解析、作答或回顾结果。

### 3.4 自动记录，减少仪式

用户不需要每天执行“生成日报”“完成所有分科待办”“再生成周报”等仪式。学习事实一旦产生，记录就已经存在；AI 日结和周结都是可选增强内容。

### 3.5 向后兼容优先于界面整洁

旧笔记、旧解析、旧日志和旧 Obsidian 文件在成功迁移并验证前不得删除、移动或覆盖。旧接口可以暂时保留为兼容层，不能在同一阶段同时迁移数据、替换 UI 和删除旧实现。

## 6. 明确不做

本轮重构不包含：

- 内置模型 API、自动调用 Gemini 或任何付费服务；
- 模拟考试、复杂组卷、算法记忆曲线、积分奖励；
- 重新清洗或重新导入书籍、政治题库和英语真题；
- 改写原书正文、OneDrive 原始资料或 MinerU 产物；
- 为追求统一而把不同题型强行改成同一种界面；
- 一次性删除旧 review/log/weekly/notebook 数据目录；
- 从零重写视觉系统。

## 7. 完成后的最简使用说明

如果最终仍需要一份复杂说明书，重构就没有成功。完成后的日常使用应当可以压缩成一句话：

> 打开“今日”，先完成上次学习回顾，再继续学习；所有笔记、作答、记录和统计由系统自动归档。
